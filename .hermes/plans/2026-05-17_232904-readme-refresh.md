## Proposed README structure

建议 README 默认使用英文，另外提供完整中文版本，并在两个版本顶部互相放语言切换链接。

推荐文件：

- `README.md`：英文默认入口，面向 GitHub / GreasyFork / 国际用户。
- `README.zh-CN.md`：中文版本，面向中文用户和作者已有中文脚本语境。

语言切换建议：

- `README.md` 顶部放：`English | [简体中文](README.zh-CN.md)`
- `README.zh-CN.md` 顶部放：`[English](README.md) | 简体中文`
- 两个版本内容结构保持一致，避免维护时信息漂移。

建议结构：

1. Hero 区
   - 标题：`# Tampermonkey Userscripts`
   - 一句话：`一些让网页更顺手的油猴脚本：阅读、复制、刷课、暗色模式、自动化小工具。`
   - Badge 可选：License、Userscript、Tampermonkey、JavaScript
   - 简短说明：脚本都围绕“少点几下、少受打扰、网页更舒服”

2. Scripts 列表
   - 不使用 Markdown 表格，改用卡片式 bullet，避免平台渲染表格问题
   - 每个脚本包含：
     - 名称（加粗标题）
     - 一句话用途（中英文描述）
     - 适用站点：直接写域名/路径，不单独打 `match` 标签

   - 避免 `·` 分隔的割裂感，同类信息用同组视觉权重

## Risks / tradeoffs

- 根 README 如果列太多细节，后续每个脚本更新都要同步维护；建议只放概要，详细说明仍放子目录 README。
- 部分脚本偏个人场景，例如 Hermchats、AnyRouter、红果视频，公开 README 要避免写得像正式产品。
- `sumbuddy-dark` 使用 `*://*/*`，README 必须提示“按需启用”，否则用户可能担心影响所有网站。
- 如果所有脚本都放 GitHub raw 安装链接，体验不如 GreasyFork；但比编造 GreasyFork 链接可靠。
- 中英双版本会增加维护成本；建议两个文件结构完全一致，更新脚本列表时同步修改。
